# 08. 알림 (Notification) 테스트 시나리오

## 알림 발생 트리거

| 이벤트 | 알림 대상 | 알림 내용 |
|--------|-----------|-----------|
| 경매 입찰 발생 | 판매자 | "새 입찰이 등록됐습니다" |
| 최고가 입찰자 변경 | 기존 최고가 입찰자 | "다른 입찰자에게 최고가가 변경됐습니다" |
| 경매 낙찰 | 낙찰자 | "경매에 낙찰됐습니다" |
| 경매 종료 | 판매자 | "경매가 종료됐습니다" |
| 결제 완료 | 판매자 | "구매자가 결제를 완료했습니다" |
| 환불 승인/거절 | 구매자 | "환불 요청이 처리됐습니다" |
| 카드 승인/거절 | 신청자 | "카드 등록 신청이 처리됐습니다" |
| 채팅 메시지 수신 | 수신자 | "새 메시지가 도착했습니다" |

---

## TC-NOTI-001: 알림 목록 조회

**우선순위**: 중  
**관련 API**: `GET /api/v1/notifications`  
**인증 필요**: 있음

### 요청
```
GET /api/v1/notifications
GET /api/v1/notifications?cursor={lastNotificationId}
```

### 확인 항목
- [ ] 200 응답
- [ ] 커서 기반 페이지네이션 동작
- [ ] 각 알림에 notificationId, type, content, isRead, createdAt 포함
- [ ] 최신순 정렬

---

## TC-NOTI-002: 알림 읽음 처리 (단건)

**우선순위**: 중  
**관련 API**: `PATCH /api/v1/notifications/{notificationId}/read`  
**인증 필요**: 있음

### 확인 항목
- [ ] 200 응답
- [ ] 해당 알림 isRead: true 변경
- [ ] 목록 재조회 시 반영 확인

---

## TC-NOTI-003: 전체 읽음 처리

**우선순위**: 중  
**관련 API**: `PATCH /api/v1/notifications/read-all`  
**인증 필요**: 있음

### 확인 항목
- [ ] 200 응답
- [ ] 모든 알림 isRead: true 변경

---

## TC-NOTI-004: 알림 단건 삭제

**우선순위**: 낮음  
**관련 API**: `DELETE /api/v1/notifications/{notificationId}`  
**인증 필요**: 있음

### 확인 항목
- [ ] 200 응답
- [ ] 삭제 후 목록에 미노출
- [ ] 타인 알림 삭제 시 403

---

## TC-NOTI-005: 알림 전체 삭제

**우선순위**: 낮음  
**관련 API**: `DELETE /api/v1/notifications`  
**인증 필요**: 있음

### 확인 항목
- [ ] 200 응답
- [ ] 이후 알림 목록 조회 시 빈 배열

---

## TC-NOTI-006: 실제 이벤트 발생 후 알림 확인

**우선순위**: 상

### 시나리오: 입찰 알림
1. User B가 User A의 경매에 입찰 (`POST /api/v1/auctions/{id}/bids`)
2. User A 계정으로 알림 목록 조회
3. 입찰 관련 알림 존재 여부 확인

### 확인 항목
- [ ] 입찰 이벤트 후 판매자(User A)에게 알림 도착
- [ ] 알림 타입(type)이 올바른 값인지 확인
- [ ] Kafka 이벤트 처리 후 알림 도착까지의 지연 시간 확인 (< 3초)
