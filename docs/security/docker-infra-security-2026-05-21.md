## 체크리스트

### 크리덴셜 하드코딩
**상태: HIGH → 수정 완료**
`docker-compose.yml`의 `grafana` 서비스에 관리자 비밀번호가 `"admin"`으로 하드코딩되어 git에 커밋되어 있었습니다. 누구든 저장소 접근 권한이 있으면 Grafana 관리자 계정에 접근할 수 있었습니다.

**해결 방법:** `${GRAFANA_ADMIN_PASSWORD:-admin}`으로 변경하여 환경 변수를 참조하도록 수정했습니다. `.env.example`에 해당 키가 추가되었으며 실제 값은 포함되지 않습니다.

---

### 컨테이너 검사를 통한 비밀번호 노출
**상태: MEDIUM → 수정 완료**
`db` 서비스 헬스체크에 `${DB_PASSWORD}`를 직접 참조하면 Compose가 호스트에서 값을 먼저 치환합니다. 결과 명령 문자열이 컨테이너 메타데이터에 저장되어 `docker inspect pocat-db` 출력에 평문 비밀번호가 노출되었습니다.

**해결 방법:** CMD-SHELL 형식과 `$$MYSQL_ROOT_PASSWORD`를 사용하여 변수 치환을 컨테이너 내부에서 처리하도록 수정했습니다.

---

### 네트워크 인터페이스 노출 — MySQL
**상태: MEDIUM → 수정 완료**
`MYSQL_ROOT_HOST='%'` 설정과 함께 포트 3307이 모든 인터페이스(`0.0.0.0`)에 바인딩되어 있었습니다. 호스트에서 실행 중인 모든 프로세스 및 같은 네트워크의 다른 기기가 MySQL에 직접 접속할 수 있었습니다.

**해결 방법:** 포트 바인딩을 `127.0.0.1:3307`로 변경하여 루프백 인터페이스로 제한했습니다.

---

### 네트워크 인터페이스 노출 — Redis
**상태: MEDIUM → 수정 완료**
Redis 포트 6379가 인증 없이 모든 인터페이스에 바인딩되어 있었습니다. 호스트에 접근 가능한 모든 프로세스가 인증 없이 Redis에 읽기·쓰기가 가능했습니다.

**해결 방법:** 포트 바인딩을 `127.0.0.1:6379`로 변경했습니다.

---

### 네트워크 인터페이스 노출 — Kafka EXTERNAL 리스너
**상태: MEDIUM → 수정 완료**
Kafka 브로커 3개의 EXTERNAL 리스너(9092, 9094, 9095)가 PLAINTEXT 프로토콜로 모든 인터페이스에 노출되어 있었습니다. 암호화나 인증 없이 외부에서 메시지를 생산·소비할 수 있었습니다.

**해결 방법:** 모든 EXTERNAL 리스너 포트를 `127.0.0.1`로 바인딩하여 로컬 호스트 접근만 허용하도록 수정했습니다.

---

### Prometheus 관리 엔드포인트 노출
**상태: LOW → 수정 완료**
`--web.enable-lifecycle` 플래그가 설정되어 `/-/quit` 및 `/-/reload` HTTP 엔드포인트가 활성화되어 있었습니다. 포트가 모든 인터페이스에 바인딩된 상태에서 인증 없이 Prometheus를 원격으로 종료하거나 설정을 재로드할 수 있었습니다.

**해결 방법:** `--web.enable-lifecycle` 플래그를 제거하고, 포트를 `127.0.0.1`로 바인딩했습니다.

---

### .dockerignore 미설정으로 인한 빌드 컨텍스트 불필요 포함
**상태: LOW → 수정 완료**
`src/`와 `build/resources/`가 `.dockerignore`에 제외 설정이 없어 Docker 빌드 컨텍스트에 포함되었습니다. 이미지 레이어에 복사되지는 않으나, 빌드 컨텍스트 크기가 증가하고 민감한 설정 파일이 빌드 데몬에 전달될 가능성이 있었습니다.

**해결 방법:** `.dockerignore`에 명시적 제외 항목을 추가했습니다.

---

### 테스트 JWT 시크릿 하드코딩
**상태: LOW (잔존, 테스트 전용)**
`src/test/resources/application.yaml`에 JWT 시크릿이 하드코딩되어 git에 커밋되어 있습니다. 파일 위치와 컨텍스트상 테스트 전용임이 명확하나, 실수로 프로덕션 시크릿과 혼동될 여지가 있습니다.

**위험 평가:** LOW. `src/test/` 디렉토리에 위치하며 테스트 전용으로 명확히 구분됩니다. 실제 프로덕션 자격증명이 아닙니다.
**권고 사항:** 해당 파일에 테스트 전용임을 명시하는 주석을 추가하면 혼동을 방지할 수 있습니다.

## 이상 없음 (PASS) 항목

### .env.example — 실제 크리덴셜 미포함
**상태: 이상 없음**
`.env.example` 파일에 실제 비밀번호나 토큰이 포함되어 있지 않습니다. 모든 값이 플레이스홀더(`YOUR_PASSWORD`, `CHANGE_ME` 등)로 구성되어 있습니다. git 커밋 안전합니다.

---

### Dockerfile — 이미지 레이어 내 시크릿 없음
**상태: 이상 없음**
Dockerfile에서 빌드 타임에 시크릿을 이미지 레이어에 굽는 동작이 없습니다. 환경 변수는 런타임에 `env_file`을 통해 주입되며, 이미지 자체에는 민감 정보가 포함되지 않습니다.
